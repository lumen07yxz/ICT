6.ComfyUI（节点+Agent+任务列表，功能页面设计上参考这个）
（1）节点四态规则 → 套用到流水线步骤条
这是性价比最高的借鉴点，直接把这套状态逻辑平移到你们的「运行详情页」：
将固定流水线步骤（数据校验 → 质量检查 → 预处理 → 模型推理 → 评价 → 生成报告）做成横向 / 纵向步骤节点
直接复用四态视觉规则：待运行灰、运行中蓝高亮 + 微动效、成功绿、失败红
答辩时实时运行任务，步骤一步步点亮，动态演示效果远胜纯文字列表，是非常出彩的展示点
（2）任务队列分层逻辑 → 优化运行列表页
运行列表页按「待运行 / 运行中 / 成功 / 失败」分组展示，比纯表格检索效率更高，状态一目了然。
可在运行详情页右侧加一个迷你常驻队列，展示当前项目的任务进度，提交任务后不用切页就能看进度，操作更流畅。
（3）上下文详情交互 → 步骤 + 右侧抽屉
点击流水线的任意步骤节点，右侧抽屉面板直接展示该步骤的：输入数据版本、参数配置、运行耗时、输出产物、日志摘要
全程不跳页，操作流畅，完美契合你们「可追溯、可复现」的核心卖点，评委点哪看哪，体验感很强。
（4）错误精准定位逻辑 → 质量阻断 / 运行失败
提交运行前前置校验：有阻断项直接标红对应步骤，禁用提交按钮，和你们的质量门控规则天然匹配。
运行失败时，直接在流水线上标红出错步骤，点开显示「错误原因 + 影响范围 + 修复建议」，不要堆砌原始日志，用户体验提升非常明显。
（5）细节
操作就近原则：把「提交运行、终止任务」等核心按钮放在流水线模块旁边，不用都堆在页面顶部，操作更顺手。
空状态统一设计：无数据、无任务的页面，统一用「图标 + 提示文字 + 引导按钮」的结构，页面完整度高，精致感强。
状态色全局统一：全平台遵循「绿成功、蓝运行中、黄警告、红失败」的语义，用户认知成本为零，专业度也更高。
