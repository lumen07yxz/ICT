2.Apache ECharts（对于图标组件的功能设计上我想采用这种，对于表格组件来说，我是想像比如comfyui那样，比如我这部分科研需要输出csv，需要出图，我就额外连接出一个csv表格组件，或者折线图组件这样的）
（1）内容优先，框架轻量化
 “界面为内容服务” 的思路：
采用浅灰侧边栏 + 纯白内容区的底色分层，减少分割线使用，弱化装饰性元素
把视觉重心完全留给科研数据、图表、报告，界面本身保持低调专业
优势：天然契合医学科研的严谨调性，答辩投影清晰通透，长时间使用视觉疲劳度低
（2）按钮分层逻辑
和 Ant Design 原生组件 100% 匹配，直接套用即可：
核心操作（批准执行、提交运行、确认审批）：实心科研蓝 / 华为蓝主按钮，视觉权重最高，突出赛题核心流程
次级操作（导出报告、刷新、上传）：描边按钮，视觉重量中等
轻量操作（筛选、展开、查看详情）：文字按钮，悬停出底色，不抢视觉重心
（3）图表设计规范（最核心）
你们本身就用 ECharts 实现可视化，直接沿用官方专业规范，效果最稳妥：
ROC 曲线图：选用低饱和多色系折线，线条粗细适中，标注清晰的坐标轴名称、单位、图例，开启悬浮 tooltip 展示精确数值，保证专业严谨。
混淆矩阵热力图：采用单色系渐变（浅蓝→深蓝），每个单元格内置数值标签，用 “颜色 + 文字” 双重标识数值，兼顾色盲友好与投影清晰度。
质量统计柱状图：用绿 / 黄 / 红三色对应通过 / 警告 / 阻断，柱顶标注数值，样式方正克制，不用圆角、渐变、3D 效果。
所有图表下方补充方法说明、数据版本标注，符合科研报告的溯源要求。
（4）布局与组件可借鉴
卡片列表布局：示例卡片的「上预览 + 下标题」结构，可以直接复用到数据集列表、论文证据卡列表、模板选择页，整齐清晰，信息层级明确。
左右分栏布局：运行详情页可以参考编辑器结构，左侧放流水线步骤 / 参数配置，右侧放结果图表 / 详情，无需跳转页面，操作效率更高。
悬浮提示交互：所有关键指标、图表都加清晰的 tooltip，答辩演示时可以交互展示细节，现场感更强。
（5）细节
所有状态坚持「颜色 + 文字标签」双重标识，不用纯颜色传递信息
重要图表预留无障碍纹理模式，体现设计周全性
常用操作（导出、查看详情）放在显眼位置，缩短操作路径
