# ICT Windows 桌面工作台视觉与体验规格

## 目标

把正式 Tkinter/ttk Windows 客户端改造成有自身识别度的科研工作台。页面需要清楚表达项目档案、数据检查、团队权限、提案审核和运行追踪，让评委和团队成员能快速看懂目前处于哪一步、下一步能做什么。

用户已明确：先前点选的「B 浅色分析工作站」是误点；此前暖纸色“研究档案台”也未达到预期，不能当作最终视觉定稿。目标是成熟、精密、具有大型桌面软件完成度的科研工作台。借鉴 VS Code、JupyterLab、napari 的信息架构，不复制其品牌、图标、配色或布局细节。

## 产品与安全约束

- 正式产品为 Tkinter/ttk 桌面客户端；`frontend/` 是停止维护的浏览器原型，不属于 Windows 安装包。
- 不改变 API 契约、访问控制、成员角色、审批门禁、提案/运行状态语义、异步队列或日志脱敏。
- 所有演示内容仍是合成样例，标记 `synthetic_only`、`research_ready=false`；不暗示真实医疗数据、临床用途或科研结论。NCCCU 医疗模块保持暂停。
- 团队令牌只保留在内存，输入始终掩码；快速开始与服务设置沿用现有校验和回调。
- 只调整展示、导航和操作可见性。批准按钮只在现有角色、模板契约、项目和数据版本校验都通过时开放。

## 视觉语言

采用原创的「深石墨科研工作台」：石墨主画布、略亮的分区面板、细而稳定的边界线、单一克制的蓝青主操作色；绿、琥珀、红只分别表示成功、待核查和错误。目标是清晰的专业工具界面，不是营销首页、暖纸色档案页或均匀卡片仪表盘。字体继续使用 Windows 自带的 Microsoft YaHei UI、Segoe UI 与 Consolas。

- 应用框架采用工作台分区：左侧任务导航、顶部项目与连接工具区、中部当前工作区、底部状态栏。减少重复页头和常驻大横幅，优先留出屏幕给研究对象和数据。
- 导航使用文字与稳定焦点状态；当前项以克制的高对比背景、窄色条和字重区分。避免依赖缺字体时会错位的装饰图标。
- 导航按研究和协作/执行工作流分组，页面范围清楚但不增加无用图标。
- 以分隔线、列、工具栏和详情检查器组织信息。只有选择/属性/状态确实构成独立对象时才用面板，不堆叠同尺寸卡片，不放大面积 Hero。
- 提案、团队项目与运行记录沿用“列表/表格 + 当前对象详情”工作方式；选中态、对象身份、权限、模板/数据版本和禁用原因彼此邻近。表格以克制的交替行底色增强横向扫读，不整行铺设状态色。
- 页面标题、当前项目、服务连接和操作各有固定位置。演示范围在底部状态栏保留一条常驻状态，不再在侧栏、页头、横幅和页脚重复占用大块空间。
- Windows 11 支持时，原生窗口标题栏与边框颜色跟随深石墨工作区；不支持的 Windows 版本使用系统默认标题栏，不能影响窗口启动或内容操作。
- 文字、选中态、禁用态、错误和焦点色均按小字号可读性核验；小窗口、125% 缩放和长内容滚动不遮挡关键操作。

## 页面结构

1. **应用框架**：压缩左侧导航和顶栏高度；顶栏同步展示当前位置、服务连接、快速开始和设置；底部状态栏常驻 `SYNTHETIC_ONLY`、`research_ready=false` 和不用于临床判断提示。工作区用石墨背景和分区面板，不重复铺设横幅。
2. **项目总览**：用一条项目摘要并列或纵向展示项目名称、用途与就绪状态；窄视口下自动堆叠。下方用紧凑资源清单展示数据版本、固定模板和最近运行。取消大幅营销式 Hero 和重复卡片，将真实状态与下一步操作放在同一视觉层级；不新增装饰图表或假数据。
3. **数据质量**：本机 CSV 预检与服务器登记 manifest 并排分区，分隔条可拖动；结果、问题原因和修复建议随面板宽度换行，长结果仍可纵向滚动；路径、错误内容和源行值仍按现有脱敏规则处理。
4. **团队项目**：令牌输入与连接状态位于紧凑工具区；成员可见项目目录位于左侧，所选项目检查器位于右侧，分隔条可拖动；表格独立滚动，详情随面板宽度换行，明确“当前账号可访问”的范围。
5. **AgentArts 提案**：左侧队列与右侧检查器组成可调整的审核工作区；待审批、模板契约、数据版本、有效期及操作者权限相邻显示；表格独立滚动，禁用原因靠近审批动作，保持现有安全门禁。
6. **运行记录**：左侧运行列表与右侧所选记录详情、时间线组成可调整的追踪工作区；结果、质量状态、Trace/版本信息和 HTML/PDF 导出按顺序呈现；列表独立滚动，详情随面板宽度换行；不增加取消或手动重试。
7. **快速开始**：同一视觉系统下的分步向导，清晰显示进度、当前任务、状态和下一步；保持地址校验、异步健康检查、角色读取、跳过登录和只读提案出口行为。
8. **服务设置/契约弹窗**：统一配色、标题、字段间距和动作顺序；错误说明清晰且不显示敏感值。模板契约采用原生只读阅读窗口，以标题、分节和等宽摘要展示身份、输入/参数/输出、权限、资源限制、状态与错误及合成范围。正文可选取复制、可滚动，禁止编辑；Esc 或“返回提案”关闭，关闭后归还焦点，不增加服务请求或审批操作。尺寸按屏幕留边，短屏保留底部动作。

## 验收

### 2026-10-21 用户实际截图修正

- 总览面板按内容自然高度排列，剩余视口空间留在内容下方，不能通过扩展权重制造空卡片。数据版本、固定模板与最近运行改为有共同值列和操作列的三行资源清单。
- 刷新动作位于页标题右侧，读取错误就近提供服务设置入口；本机 CSV 预检不依赖服务恢复。总览错误和读取提示不带到其他页面。
- 刷新失败时保留已读取的同一服务快照，明确显示“上次读取”；切换后端地址时清掉旧快照，不能混用不同服务的登记信息。
- 状态栏先于可扩展内容预留空间并按宽度换行。初始窗口根据 Tk 当前屏幕坐标限制宽高，为标题栏和任务栏留边，最小窗口不超过初始尺寸；实际缩放效果仍需窗口截图复核。
- 原生窗口复查补充：表格、输入框和分隔线统一暗色边界；空设置错误不显示，校验失败才出现。质量、提案和运行页提供直达团队连接入口，导航不提交令牌；令牌栏输入框可收缩。向导“上一步”在继续动作左侧，窗口与安装程序使用工作台几何标记。

- 所有现有桌面测试通过，新增导航状态和空错误态的行为测试通过。
- 总览、质量、项目、提案、运行、快速开始和设置页面均在 Windows 可见窗口逐页检查，验证小窗口与主要操作可见。
- 关键交互仍绑定原有方法；权限/审批边界测试不回归；令牌不落盘、不进入日志。
- 拖动分隔条后说明文字按可用宽度换行；关闭主窗口会取消待执行的轮询和布局回调，不能留下失效的 Tk 回调。
- `compileall`、`git diff --check`、桌面全量单元测试及安装包构建通过；最终记录实际测试数量、构建结果与已知限制。

## 参考来源与适配

- [VS Code Workbench layout](https://github.com/microsoft/vscode-docs/blob/main/docs/configure/custom-layout.md)：参考主侧栏、可选辅助侧栏、中心内容、Panel 与状态/工具区域的职责分离，以及密度可调思路；本项目不实现拖拽停靠。
- [JupyterLab Interface](https://jupyterlab.readthedocs.io/en/stable/user/interface.html)：参考工作区、侧栏、主工作区与右侧检查器的分层，并让当前对象对应当前工具上下文。
- [napari Quickstart source](https://github.com/napari/docs/blob/main/docs/getting_started/quick_start.md)：参考选中研究对象后就近展示图层属性和控制项的方式；不引入图像查看器能力。
- 适配目标是 Tkinter/ttk 能可靠实现的左导航、顶部工具区、中心工作区、对象详情区和底部状态栏，不为追求外观引入新 UI 框架或复制竞品皮肤。
