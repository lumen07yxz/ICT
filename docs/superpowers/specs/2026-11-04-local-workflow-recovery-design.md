# 本机工作流中断恢复设计

## 目标

依据 ReproForge 报告，为本机静态 DAG 增加由用户显式发起的中断恢复。Runtime 异常重启后，用户可以从原运行创建一条新运行，沿用原冻结的 `ExecutionPlan`，恢复已完成节点的持久化输出，并继续调度未完成节点。原运行记录保持不变。

## 现状与问题

本机运行在 `local_workflow_runs` 中保存冻结执行计划，`local_workflow_run_events` 逐步保存节点状态。Runtime 启动时，`mark_incomplete_runs_failed()` 会把仍处于 queued/running/waiting_external 的运行标记为 `failed / LOCAL_WORKER_RESTARTED`。当前节点输出主要在整次运行结束时写入 `local_workflow_node_runs`，因此运行进程在中途退出时，事件可能显示节点成功，但恢复所需的输出没有持久化。

## 用户流程

1. 用户打开一条 `LOCAL_WORKER_RESTARTED` 失败运行。
2. 运行详情解释：恢复会创建新的运行记录，保留原记录，并按原执行计划继续；旧运行不会被改写。
3. 用户明确点击“恢复运行”。仅此动作提交恢复请求；Runtime 启动、重新连接或读取运行记录均不会触发执行。
4. 新运行显示其来源运行。能安全恢复的已完成节点标记为 `RESTORED`；其余节点依赖就绪后正常调度。可复用缓存时继续按现有缓存机制处理。
5. 如果恢复过程中 Runtime 再次中断，新运行也可以用同一流程恢复。

## 执行与持久化语义

- 仅对本机 Runtime 重启造成的 `failed / LOCAL_WORKER_RESTARTED` 提供该入口。其他失败仍由用户使用常规运行操作处理。
- 恢复严格使用来源运行保存的 `execution_plan_json` 与 `plan_hash`，不读取当前编辑器草稿重新编译。恢复前仍执行本机准入和执行端可用性检查。
- 为确保断点可用，调度器在节点成功时先将输出、节点状态和对应事件持久化；该写入须在同一数据库事务内完成。持久化失败时不得把节点作为可恢复成功结果释放给下游。
- 新运行记录直接关联来源运行，并有独立 `run_id`、节点记录与事件序列。来源运行及其事件/产物不可变。
- 恢复前只复用来源运行中具有完整输出的成功节点；产物引用应通过本机 Artifact Store 校验。缺少输出或产物校验失败的节点不标为 `RESTORED`，由本次显式恢复运行重新调度，并继续受现有签名缓存约束。
- 调度器把 `RESTORED` 视作可满足依赖的成功状态。未完成节点只在用户显式恢复后运行；程序启动本身不自动调用节点，包括网络节点。
- 对同一来源运行若已有活动恢复子运行，重复请求应返回该活动运行或明确冲突，避免双击创建并发副本。
- 运行事件需记录恢复来源、被恢复节点数和重新调度节点数，不记录原始 CSV 单元格或其他大块数据。

## 范围

包含：SQLite 本机运行关系与增量兼容、节点完成时的持久化、调度器恢复输入、一个本机恢复 API、运行详情中的恢复入口和来源标识、相关错误提示。

不包含：任意运行时暂停、自动重试策略、人工介入/审批节点、平台 Worker、跨设备恢复、容器沙箱、GPU 调度、第三方科研结论判断。

## 验收标准

- Runtime 冷启动只把未完成运行标记为可识别的中断失败，不启动工作流或产生网络请求。
- 仅符合中断条件的运行显示恢复入口；用户确认后创建新 `run_id`，其执行计划哈希与来源运行一致，来源记录保持不变。
- 已成功且输出/产物完整的节点在新运行中为 `RESTORED`；未完成节点按 DAG 依赖执行，独立分支仍按现有调度策略隔离故障。
- 重启后再次恢复时，最新子运行已持久化的成功节点可再次复用；无法安全复用的节点会重新执行而不会伪装为已恢复。
- 重复点击不会创建同时执行的恢复子运行；平台未连接时功能仍在本机可用。
- CSV 文件、工作流、执行记录和产物仍留在本机；恢复报告沿用原结果的科学性标记，不将结构检查/描述统计提升为科研结论。

## 文件边界

- `backend/app/services/local_runtime_store.py`：来源运行关系、原计划克隆、节点输出与事件的事务持久化、恢复候选输出读取。
- `backend/app/services/workflow_scheduler.py`：接受经验证的已完成输出，恢复节点状态并满足下游依赖。
- `backend/app/local_runtime.py`：恢复 API、活动子运行防重与后台执行接线。
- `frontend/src/api/localRuntime.ts`：恢复请求和恢复来源字段类型。
- `frontend/src/App.tsx` 及当前运行详情样式：条件化恢复入口、说明确认、来源运行呈现。
- `task.md`、`progress.md`：更新切片目标与验收进度。

## 风险与兼容

旧版本运行可能没有节点级输出快照。此类节点不能声称为已恢复：若 Artifact Store 或签名缓存无法提供结果，则在用户显式恢复后重新执行。恢复 UI 必须说明这是新运行，并让用户可以从事件中区分“恢复输出”和“重新执行”。数据迁移只添加可空来源字段，不重写既有运行数据。
