# ICT 科研工作台界面设计规格

## 目标

把 Windows Tkinter 工作台做成有辨识度的科研软件界面：信息密度适中、状态可信、操作紧邻上下文、在不同屏幕尺寸上清晰可读。保留已确认的深石墨方向，避免套用营销网站、AI 生成式渐变、伪数据可视化和无业务意义的装饰。

## 方向与取舍

- **采用：深石墨科研工作台。** 用低饱和矿物青作为交互强调色，辅以一致的灰蓝中性表面；按区域和间距表达层级。项目身份、服务连接、数据范围和可执行步骤必须各有清楚位置。
- **不采用：浅色分析站。** 用户已说明先前选择为误点，当前方向仍以深色工作台为准。
- **不采用：营销式仪表盘/网站重构。** 产品交付是原生 Windows 客户端，主导航、状态栏、检查器和表格需要像桌面研究工具一样服务真实工作流。

## 信息架构

1. 固定顶栏只承载工作区路径、服务状态和全局入口（快速开始、服务设置）。
2. 页面页头统一呈现标题、简洁上下文和当前页高频动作，减少操作散落。
3. 项目总览先给项目身份和就绪边界，再给可直接进入的四个工作步骤，最后列数据版本、模板与最近运行。
4. 数据质量页明确区分“本机 CSV 预检”和“服务器登记清单”；不暗示本机文件上传。
5. 团队、提案和运行页采用紧凑列表与相邻检查器，状态说明靠近数据表；操作继续受既有角色与后端边界约束。

## 视觉系统

- 深石墨、蓝灰表面、细分隔线；通过背景明度、留白、字重区分层级，避免所有内容都被同一种大面板包起来。
- 统一 Windows 中文 UI 字体；提高正文、次级文字和页标题的可读性；项目 ID、版本、Trace 使用等宽字。
- 青色只表示当前操作或当前导航；绿色、琥珀、红色只用于语义状态。状态文本始终可独立阅读，不只依赖颜色。
- 表格行距、标题和控件间距按 4px 节奏设计；键盘焦点、悬停和禁用状态保持明显。
- 首屏适配窗口高度，不通过伪指标、假运行数据、背景图片或渐变填充空白。

## 当前实现边界

- 本轮先交付共享类型/颜色/控件样式，以及可操作的总览工作路径；在此之上逐页打磨质量、团队、提案、运行页和对话框。
- 不更换 Tkinter/ttk，不引入新的 UI 依赖，不改后端 API、授权逻辑、提案审批规则、运行边界或科研数据声明。
- 旧 `frontend/` 浏览器原型不作为当前 Windows 软件的交付目标。

## 参考原则

- VS Code Workbench：固定工作区区域各有职责，状态栏保持精炼。
- GitHub Primer NavList：导航说明当前视图并通过恰当分组减轻扫描成本。
- Microsoft Fluent 2：以邻近关系和一致节奏表达内容关联，导航简洁、可扫读。
- 仅借鉴以上交互原则，不复刻产品外观。来源链接见项目 `findings.md`。

## 验收

- 正文及小字的字号达到规格，核心文字在对应背景上保持可读；语义色不被用作装饰。
- 总览四个步骤均可直接进入对应页面，入口保持离线可用且不触发后台写操作。
- 页面、服务、授权和合成边界状态不丢失；原有 API、令牌处理、CSV 本机预检、审批权限和运行限制不改变。
- 单元回归与静态编译通过，Windows 安装包能够构建且版本信息匹配。
- 当前窗口存在人工操作时，停止 Computer Use；不把旧安装版截图当作最新包验收结果。
