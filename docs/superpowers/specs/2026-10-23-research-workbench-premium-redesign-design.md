# ICT 科研工作台：档案与协作界面改版规格

## 目标

把现有 Windows 工作台从“功能齐全但像一组深色面板”提升为专业科研软件：先呈现研究项目身份、数据来源与可审计状态，再为协作审核提供高效的列表和检查器。工作台须稳重、克制、易扫读，并在常见窗口尺寸下保持操作可达。

## 已确定的设计方向

- 沿用深石墨与低饱和矿物青蓝主题。此前浅色方向是误点，不能作为产品主题。
- 采用“科研档案台 + 协作工位”的信息组织：总览像项目档案，质量页像数据核验台，团队/提案/运行页像带检查器的审核工作区。
- 参考 VS Code Workbench 的区域职责、GitHub Primer 的清晰导航状态、Microsoft Fluent 2 的间距和网格原则；不复制品牌皮肤。
- 不使用渐变、宣传式大标题、伪指标、假活动图或装饰性卡片。层级由排版、对齐、留白、细分隔和少量语义色表达。

## 共享框架

- 左侧导航保留“研究”和“协作与执行”两组，当前页具有清楚的背景和边缘指示；图标保持简洁并服务识别。
- 顶栏集中工作区路径、服务状态、快速开始和服务设置。页内标题行承载标题、解释和当前页主操作，避免动作散落。
- 主工作区采用深色底、略亮的内容面和更浅的编辑/列表底。只有需要聚焦或承载输入的区域使用边框。
- 底部持续显示 `SYNTHETIC_ONLY` 范围。连接状态、数据质量、科研就绪状态各自独立表达，不能互相替代。
- 中文正文保持易读，辅助信息不低于 9pt；ID、版本、哈希和 Trace 使用等宽字。所有颜色组合满足小字对比度要求，焦点和禁用状态可见。

## 五个页面

### 项目总览

首屏从项目名称、用途、ID 和科研就绪状态开始。就绪状态附清楚原因，服务断连仅作为连接问题显示。研究路径显示四个真实入口（团队项目、CSV 检查、提案复核、运行追踪），使用连续编号和对齐关系，不制造完成比例。数据版本、固定模板、最近运行构成紧凑资源台账；本机 CSV 检查在断连时仍可直达。

### 数据质量

把本机 CSV 预检和服务器登记清单分成两个有明显来源标签的工作区。本机文件名、质量结论、问题和修复指引放在本机工作区；服务端数据版本、读取状态和报告放在远端工作区。明确本机文件不上传，服务器报告仅读取已登记的合成 manifest。区分阻断、警告、通过、等待和失败状态，保留错误的具体修复建议。

### 团队项目

访问令牌区和项目工作区分离。令牌输入掩码，连接后立即清空输入框；令牌只驻留当前进程、不进入日志或配置。列表显示当前账号有权访问的项目，检查器显示项目 ID、角色、领域和数据版本；空状态说明如何连接。

### 智能体提案

提案队列和检查器采用一致的列表/详情网格。状态、模板、数据版本和有效期便于横向扫描。选中后在检查器查看配置、模板匹配、权限与失效原因；底部操作区持续显示只读模板说明和受角色/契约校验控制的批准操作。不可操作时显示原因。批准只沿用现有流程，不增加任务能力。

### 运行记录

列表用于扫描状态、模板与提交时间；检查器并列呈现运行字段、持久化事件时间线和报告导出。导出动作固定在详情底部且仅在当前运行可导出时启用。不新增取消、重试或其他写操作。

## 对话框

- 快速开始保持四步流程；标题、步骤进度、可滚正文和固定底部操作与主窗口同一视觉体系。错误靠近字段或动作，继续按钮只在现有条件满足时启用。
- 服务设置统一输入、校验、错误、保存反馈；HTTPS/本机回环校验和设置持久化规则不变。
- 固定模板说明提供清晰分节、可选择/复制长文本、滚动条与固定返回操作；契约字段、限制和合成边界完整保留。

## 响应式与交互

- 支持 1200×800、1366×768 常用窗口；最小支持窗口和 125% DPI 下不裁切关键字段、主要操作或范围说明。
- 详情长文本在详情区域内滚动，滚动到边界后可继续滚动页面；长页可滚动，固定操作仍可达。
- 页面切换、悬停、键盘焦点、加载、错误、空、禁用和选中状态都有可辨认样式与文字语义。

## 范围与安全边界

保持 Tkinter/ttk，不引入新运行依赖，不改变 API、服务地址校验、角色授权、提案审批、模板契约、运行参数、数据处理和报告导出逻辑。医疗模块仍未纳入本阶段。无团队令牌、不连公网、不批准提案、不启动任务作为界面改版的默认验收条件。

## 验收

- 五个页面和三类弹窗使用统一主题，状态与动作在各自上下文内可识别。
- 新增行为/可访问性断言先失败再实现；桌面全量测试、静态编译和 diff 检查通过。
- Windows EXE 与安装包版本一致，归档含主窗口、主题和弹窗模块。
- 构建后的真实窗口需逐页、逐弹窗并在常见尺寸/125% DPI 检查。未运行新版前只报告源码和自动测试结果，不宣称实机验收完成。
