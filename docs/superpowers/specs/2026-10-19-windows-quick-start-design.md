# Windows 原生快速开始向导设计

**状态：** 已按用户确认的快速开始方案编写，范围限于 Windows 桌面客户端。

## 目标

让新成员从桌面工作台完成服务地址配置、API 连通性检查、团队项目角色确认，并能继续查看固定模板说明。向导复用现有只读服务；团队访问令牌只在当前进程内存中使用。跳过团队登录仍可完成向导。任何步骤都不批准提案、不创建运行、不启动 Worker。

## 当前项目依据

- 产品入口是 `desktop/ict_desktop/main_window.py` 中的 Tkinter/ttk 主窗口；`frontend/` 是旧网页原型，不属于当前交付路径。
- “服务设置”已有远程 HTTPS/本机回环地址校验、地址保存和概览重载；`DemoProjectApiClient.check_health()` 可用来做 API 连通检查。
- “团队项目”已有掩码令牌输入、`GET /api/v1/projects` 成员范围读取和操作者/查看者角色显示。连接后还会读取最近运行记录，这些都是只读请求。
- “智能体提案”已有只读提案列表和固定模板契约窗口；模板说明要求用户从一条可见提案进入。

## 方案选择

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| Windows 原生四步向导，复用现有客户端和页面流程 | 一条连续路径；沿用已有地址校验、权限和模板契约逻辑 | 需要安全地编排异步健康检查和团队项目读取 | **采用；用户已确认** |
| 首页常驻四项检查清单 | 可以同时看到所有状态 | 用户需要自行判断操作顺序，重复已有页面入口 | 不采用 |
| 网页式引导页 | 可自由排版 | 改变已确认的 Windows 桌面交付形态 | 不采用 |

## 交互流程

向导由主窗口工具栏的“快速开始”按钮手动打开，不在每次启动时自动弹出。使用原生 `Toplevel`，显示当前步骤、状态说明、上一步、下一步和关闭操作。

1. **设置后端地址**：地址输入框预填当前服务地址。用户点击“保存并继续”后复用现有 URL 校验与保存逻辑；本机回环 HTTP 可用，远程服务必须为 HTTPS。持久化内容只有服务地址。
2. **检测 API**：点击“检测 API”后在后台线程调用 `check_health()`；Tk 控件只由创建它的主线程更新。成功显示“API 可连接”，不把服务存活解释为科研就绪。失败显示安全错误和重试入口。
3. **连接团队项目**：令牌输入框使用掩码；连接后复用现有成员范围项目读取，并在向导中显示可访问项目及角色。连接失败可重试，也可选择“跳过团队登录”。跳过不会提交未连接的令牌，也不会清除已经存在的会话。
4. **查看固定模板说明**：说明提案及模板契约的只读边界，并提供“打开提案页”入口。点击后先关闭向导，再打开现有提案页；用户选择一条可见提案后使用已有“查看固定模板说明”功能。没有可见提案时按现有空状态提示，不创建提案。

用户可以随时关闭向导；已保存的服务地址保留，令牌遵守现有内存生命周期。健康检查和项目连接使用队列/`after` 在主线程回填结果；关闭向导后忽略迟到回调。向导不新增任何服务端写接口。

## 边界与错误处理

- 地址不符合已有校验规则时显示安全错误，停留在当前步骤，不更换客户端或保存地址。
- API 检查失败时允许重试或关闭；团队登录失败时允许重试、跳过或关闭。
- 向导不在日志、设置文件、计划文件或错误提示中输出访问令牌。
- 查看模板说明依赖已登录成员可见的提案；没有提案时，向导说明如何从提案页继续，不伪造服务器契约。
- 所有步骤都没有批准按钮，也不调用审批 API、提案创建 API 或运行启动 API。
- NCCCU 医疗数据、外网部署、AgentArts 平台调用和运行执行不属于此向导范围。

## 验收标准

1. 桌面主窗口能打开原生四步向导；向导不自动弹出。
2. 地址校验/保存失败时留在第一步；有效地址只保存 URL，并可继续健康检查。
3. 健康检查在后台运行，成功和失败结果都在 Tk 主线程显示；失败可重试。
4. 团队令牌被掩码，角色由真实的成员范围读取结果显示；令牌不写入设置文件或日志。
5. “跳过团队登录”能到达模板说明步骤，且不会触发团队 API 请求。
6. “打开提案页”跳转现有只读提案/模板说明流程，不调用写接口，不批准、不创建或执行任务。
7. 覆盖关闭期间迟到响应、无可见项目、健康检查错误、URL 校验失败和跳过登录等回归用例。
8. 桌面全量测试、`compileall`、`git diff --check` 通过；更新 Windows 安装包并做静默安装/卸载验收。
