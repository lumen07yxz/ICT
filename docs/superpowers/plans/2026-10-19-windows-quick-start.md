# Windows 原生快速开始向导实施计划

## 目标

在 Windows Tkinter 桌面客户端加入手动打开的四步快速开始向导：保存后端地址、检查 API、连接团队项目并确认角色、打开现有提案页查看固定模板说明。令牌仅供当前进程内存使用；跳过团队登录不发起团队请求。流程保持只读，不批准、不创建提案、不启动运行。

## 实施任务

### 1. 先写向导行为测试

- 新建 `desktop/tests/test_quick_start.py`，先覆盖四步文案和导航、无效地址不保存、健康检查后台成功/失败与重试、令牌掩码及连接后清空输入、跳过登录不调用连接回调、关闭后丢弃迟到健康检查、提案页出口只调用既有导航回调。
- 运行该测试，确认在向导模块尚不存在时按预期失败。

### 2. 实现独立 Tk 向导

- 新建 `desktop/ict_desktop/quick_start.py`，用原生模态 `Toplevel` 实现四步界面。
- 通过回调注入服务 URL 保存、当前 API client、团队连接、团队状态读取及提案页导航，避免向导复制业务权限逻辑。
- 健康检查放入后台线程；结果用线程安全队列返回，并由 `after` 在 Tk 主线程更新控件。关闭时取消轮询并忽略迟到结果。
- 不记录令牌；连接回调后立即清空向导输入框。跳过操作只清空当前未提交输入，不清除已有团队会话。

### 3. 主窗口集成与集成测试

- 在 `desktop/ict_desktop/main_window.py` 工具栏加入“快速开始”入口。
- 抽取共享的服务地址校验、持久化和 client 切换逻辑，让服务设置对话框和向导共用同一规则。
- 提供向导连接回调，调用既有 `connect_team_projects()` 的只读 GET；从现有项目缓存读取项目和角色；跳转前关闭向导，再调用 `show_proposals()`。
- 先给 `desktop/tests/test_main_window.py` 添加集成测试，验证工具栏能打开向导、成功连接显示角色，以及提案入口不触发任何写入动作；测试失败后再改主窗口。

### 4. 回归、打包和记录

- 运行向导与主窗口目标测试、桌面全量测试；执行 `compileall` 和 `git diff --check`。
- 静态检查向导只访问健康检查和现有成员范围只读列表，不包含提案创建、审批或运行启动调用。
- 保留 0.1.20 产物，更新 Inno Setup 版本至 0.1.21，构建 EXE 与安装包，记录 SHA-256。
- 做静默安装/卸载验收，不启动安装后的可见窗口，不审批提案或运行任务。
- 更新 `task.md` 记录实现、测试和安装包验收，并保留“公网上线、AgentArts 实测与 NCCCU 医疗模块仍暂停”的现状。

## 验收标准

1. 桌面主窗口有手动“快速开始”入口；界面为原生 Windows 桌面窗口。
2. 地址按现有规则校验并复用原有服务地址设置保存方式；无效值不保存。
3. 健康检查异步执行，可安全重试；失败信息不泄露异常正文。
4. 团队 token 掩码显示、不落盘、不写日志；连接复用现有只读流程并显示真实角色；跳过不调用团队 API。
5. 模板说明步骤只导航到既有提案页；无审批、提案创建和运行启动请求。
6. 目标测试与桌面全量测试通过，静态检查通过；0.1.21 安装包静默安装/卸载成功。
