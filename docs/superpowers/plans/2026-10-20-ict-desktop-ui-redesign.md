# ICT Windows 桌面 UI 改版实施计划

> **给执行者：** 严格按步骤完成。遵循 `test-driven-development`：先添加行为测试、观察失败，再实现；完成每步后复跑针对性测试。不要改后端 API、权限、审批或演示数据语义。

**目标：** 将正式 Tkinter/ttk 客户端从暖纸色档案页调整为成熟、精密、数据优先的桌面工作台，优化分区、密度、选中对象详情与全局状态反馈。

**设计：** 详见 `docs/superpowers/specs/2026-10-20-ict-desktop-ui-redesign-design.md`。用户撤销误点的 B 浅色方向，并指出暖纸色实现也不符合预期。采用深石墨中性主区、克制蓝青色操作、左侧任务导航、顶部项目/连接工具区、中心工作区和单条底部合成状态；借鉴 VS Code Workbench、JupyterLab、napari 的信息分区，不复制品牌与皮肤。

**产品：** Python Tkinter/ttk、Windows、现有 FastAPI 客户端。保持现有 API/模型和所有业务回调。

## 文件范围

- 新增 `desktop/ict_desktop/ui_theme.py`：集中颜色、字体、ttk 样式与按钮交互状态。
- 修改 `desktop/ict_desktop/main_window.py`：应用框架、页头上下文、导航状态、状态提示、页面排布、表格呈现、设置/模板弹窗。
- 修改 `desktop/ict_desktop/quick_start.py`：沿用共享视觉系统重做分步层级，保留异步与数据行为。
- 新增 `desktop/tests/test_ui_design.py`：导航选中状态、页面上下文、空错误条和工作台主题行为测试。
- 更新 `task.md` 与 `memory/ict/desktop-quality.md` 记录决定和验收。
- 改动已有源/任务/记忆文件前使用已有副本，或为当下内容创建一次带日期的 `_copy` 文件；不覆盖历史副本。

## 步骤

### 1. 建立行为测试并确认失败

- 测试页面导航后只有目标按钮呈活动样式，标题及上下文同步。
- 测试初始空错误提示不映射；错误出现时可见，清空后隐藏。
- 测试页面导航状态与上下文可见，避免只检查主题常量。
- 运行 `desktop/tests/test_ui_design.py`，确认失败原因对应缺失行为。

### 2. 实现深石墨共享视觉系统

- 调整主题模块中的语义颜色 token 和样式；对 ttk.Treeview、按钮、标签、输入框、滚动条给出一致暗色状态与焦点提示。
- 保留旧样式名兼容现有控件，避免逐个改业务逻辑造成回归。
- 运行主题与导航行为测试。

### 3. 压缩主窗口框架并重排总览

- 更新窗口尺寸、左侧任务导航、紧凑顶栏、页头上下文、底部合成范围状态和动态错误/加载状态；移除重复的大型演示横幅。
- 总览改为项目身份、就绪状态和数据/模板/运行信息组成的数据优先工作视图，不使用大幅 Hero 或装饰图表。
- 在 `show_*` 方法中统一设置活动导航和页面标题/说明。
- 运行新增测试及总览相关现有测试。

### 4. 优化质量与团队项目工作区

- 质量页区分本机 CSV 与服务器 manifest；提高结果、问题、建议和操作之间的扫描效率。
- 团队页优化访问令牌区、成员范围列表和所选项目详情的相邻层级与空状态。
- 运行对应的既有质量、服务客户端和团队访问测试。

### 5. 优化提案与运行对象检查器

- 保留表格选取和所有动作回调；列表/详情并置，提高提案合同/权限和运行状态时间线的可读性。
- 不开放不满足条件的审批，不引入新的运行行为。
- 运行审批门禁、竞态、运行事件和报告导出测试。

### 6. 优化快速开始与弹窗

- 用共享样式重做步骤标题、进度、字段和状态区；保留原有地址/token/健康检查行为。
- 统一服务设置和固定模板契约对话框视觉。
- 运行快速开始异步关闭、重试、token 掩码和边界测试。

### 7. 全量验收与安装包

- 先跑新增测试与桌面全量：`.venv\Scripts\python.exe -m unittest discover -s desktop/tests -v`。
- 跑 `compileall` 与 `git diff --check`，检查敏感 token/只读边界和文件变更。
- Windows 实际窗口逐页视觉检查，含默认窗口、窄窗口、快速开始与关键弹窗；修复可见问题后复验。
- 用项目锁定依赖构建 PyInstaller EXE 和 Inno Setup 安装包，记录哈希与安装/卸载检查结果。
